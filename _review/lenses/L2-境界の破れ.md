## この成果物が主張している防御

このサーバは MCP 経由で LLM に Backlog の課題・Wiki を操作させます。設計上、次を**防御として主張**しています（`README.md` と `DESIGN.md` に記述あり）。あなたの仕事は**その主張を崩しにいくこと**です。

1. **ポリシーによる権限境界** — `backlog-policy.json` で許可したプロジェクトの、許可したツールだけ。引数で範囲を広げられない（`src/policy/policy.ts`, `src/tool/tools.ts`）
2. **fail-closed** — 設定・ポリシー・マスタ解決のどれかが失敗したら起動しない。静かに全開放しない（`src/server.ts`）
3. **添付ファイルの読み取り面の閉じ込め** — ローカルファイルを読むのは `src/attach/localFile.ts` だけ。ルート外・自分自身の設定ファイル・監査ログは読ませない
4. **秘密の非漏洩** — API キーがログ・エラーメッセージ・MCP 応答に出ない（`tests/leak.test.ts` がある）
5. **監査ログ** — 操作が記録される。書けなければ起動しない（`src/mcp/audit.ts`）
6. **untrusted 本文の隔離** — Backlog 利用者が書いた本文を `<untrusted>` で囲んで prompt injection を緩和（`src/tool/untrusted.ts`）

## 攻撃者モデル（誰が何を制御できるか）

- **A. 悪意ある/誘導された LLM** — ツールの引数を任意に作れる。`projectKey`・`issueKey`・パス・ソート・オフセット・カスタム属性 ID などを自由に指定できる
- **B. Backlog 側の書き手** — 課題本文・コメント・Wiki・添付ファイル名を制御できる。ここに書いた文字列が MCP 応答に載って LLM に届く（間接 prompt injection）
- **C. 設定を間違えた運用者** — ポリシーの記法を誤る、環境変数を空にする

## 探すべき破れ方（優先順）

1. **ポリシー迂回** — 許可外プロジェクトのデータに到達できる引数の作り方。ID とキーの混同、大文字小文字、Unicode 正規化、プロジェクトキーのパターン `^[A-Z0-9_]+$` と課題キー `^([A-Z0-9_]+)-\d+$` の突き合わせの穴。「キーで検査して ID で実行する」ような**検査と実行の対象がずれる**構造（TOCTOU 的な二重解決）
2. **パストラバーサル / 意図しないファイル読み取り** — `src/attach/localFile.ts` の `realpath` / `relative` / `isAbsolute` の使い方。シンボリックリンク、`..`、大文字小文字を区別しないパス、ルートと同名接頭辞のディレクトリ（`/root` に対する `/rootX`）、`selfPaths` / `selfDirs` の除外の抜け
3. **秘密の漏洩** — API キーが例外の `cause` チェーン・HTTP エラー本文・監査ログ・stderr・MCP のエラー応答に載る経路。`got` の例外は URL やヘッダを持ちうる
4. **fail-open** — 例外を catch した先で、拒否ではなく素通りになる分岐
5. **監査ログの汚染・回避** — 記録されずに通る操作、ログにサードパーティの文字列を注入して行を偽装できる箇所（改行の混入）
6. **untrusted 囲みの脱出** — 本文に `</untrusted>` 相当を書いて囲みから抜けられるか。`src/tool/untrusted.ts` の無害化が実際に効くか
