## あなたが担当する失敗モード（これだけを見る）

**正常系・準正常系の内部矛盾と、実行時に壊れる経路**です。具体的には:

1. **エラー経路** — catch の握りつぶし、`cause` の欠落、例外の型の取り違え、`SuppressedError` の向き（本来の原因は `suppressed` 側）
2. **境界値** — 空配列・1件・上限付近・0件・undefined と null の取り違え、off-by-one（特にページング・件数の上限・`probeCount` のような「1件多く引いて打ち切りを検出する」実装）
3. **非同期** — 未 await の Promise、`Promise.all` にすべき直列、競合、`AbortSignal` の伝播漏れ、`using` スコープ内の `return` に `await` が無い（破棄が解決より先に走る）
4. **リソース解放** — ファイルハンドル・ストリームの解放漏れ（`src/attach/localFile.ts` が `node:fs/promises` の `open` を使っている）
5. **沈黙の失敗** — 黙って空を返す・黙って切り詰める。打ち切った事実が戻り値に現れない設計
6. **型の嘘** — `as` / `!` / 検証を伴わない型パラメータで、コンパイラを通るが実行時に落ちる箇所

**担当外（見つけても報告しない）**: セキュリティ上の攻撃可能性、MCP クライアント/LLM から見た使い勝手、コーディング規約の条文違反、命名の好み。他の視点が担当しています。
