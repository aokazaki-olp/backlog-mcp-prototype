### 実測 — L4-5 は「テストを足す」だけでは閉じない（4つの角度から裏を取った）

`config.ts:128` の保険に到達するには、`decryptApiKey` が `encrypted:` で始まる値を
返さなければならない。dotenvx 2.23.0 で4通り試した（`scratchpad/probe-l45.mjs` / `probe-l45b.mjs`）。

```
[平文 .env に encrypted: 接頭辞]       throw: DECRYPTION_FAILED
[公開鍵つき + 壊れた暗号文]            throw: DECRYPTION_FAILED
[平文そのものが "encrypted:..."]       throw: DECRYPTION_FAILED   ← 復号は成功するのに送出する
[平文が "encrypted:" ちょうど]         throw: DECRYPTION_FAILED
```

3件目が要点。**正しく暗号化されていて復号にも成功するのに送出する。**

上流には、`config.ts:128` と**同じ述語を持つ後検査**がある。

- `node_modules/@dotenvx/dotenvx/src/lib/resolvers/envs.js:18` の `unresolvedEncryptedErrors` が、
  **解決後の値**を走査して `encrypted(value)` なものを `DECRYPTION_FAILED` にする
- その述語は `@dotenvx/primitives` の `encrypted(v) => v.startsWith('encrypted:')`
  （実物を呼んで確認: `'encrypted:x'` → `true`、`'ENCRYPTED:x'` / `'encrypte:x'` / `''` → `false`）
- `src/lib/main.js:118 / 162 / 357` で、`strict` なら送出する

**ただし、この後検査が上の4件を止めているのではない（訂正）。**
`unresolvedEncryptedErrors` を `return []` に潰しても**送出は変わらなかった**（実測）。
止めているのは復号段のどこかで、**内部の出所は特定していない**。
一度「後検査が止めている」と書いたが、それは**プローブが答えていない問いの答えとして読んだもの**
（台帳の較正が挙げる形の4度目）。**測った事実だけを残す。**

- 測ったこと: この入力クラスは dotenvx が `DECRYPTION_FAILED` で送出する（4通り・再現あり）
- 測ったこと: 同じ述語の後検査が上流に存在する（出典を開いて確認）
- **測っていないこと**: どちらの機構がこの入力を止めているか

`ConfigOverrides.resolveApiKey` は `decryptApiKey` を**丸ごと置き換える**ので、
この保険はその経路からも通らない。**現行版では到達経路が存在しない。**

**ただし依存は `^2.23.0`（caret）** なので、上流が変われば保険が生きる余地は残る。
**保険そのものを消す理由にはならない。** 判断は「到達させる口を作るか」だけにある。**段階4 で4案を出す。**

### 欠陥の種類を言葉にして横断で探した

**種類**: 「**外部応答の形を検査する枝のうち、テストのハーネスが正常系を既定にしている層のものが落ちている**」。
