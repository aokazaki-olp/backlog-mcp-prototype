# \_review — レビュー対応の追跡

`src/` の多角レビュー（2026-09-06 開始、版 `5055619`）への**対応作業**を追跡する場所。

レビューそのものの記録は台帳が持つ。ここが持つのは**採ると決めた指摘を成果物へ落とすまでの過程**で、
両者は `multi-angle-review`（統合まで）と「指摘修正のあり方」（適用）の分担にそのまま対応する。

| 置き場                                    | 何を持つか                                     |
| ----------------------------------------- | ---------------------------------------------- |
| `obsidian/ai/reviews/2026-09-06-…台帳.md` | 指摘一覧・根の導出・却下理由・収束判定（台帳） |
| `obsidian/ai/logs/{date}.md`              | 作業ログ（経緯）                               |
| **このディレクトリ**                      | 根ごとの段階1〜4の出力（修正方針）             |

## `borrowed/` — 別プロジェクトからのコピー

**正本は `aokazaki-olp/backlog-mcp` の `_tmp/borrowed/`。ここでは編集しない。**
更新するときは正本を直してコピーし直す（`diff -r` で差分ゼロを確認する）。

`.claude/skills/` / `.agents/skills/` に置かないのは、borrowed 側の README が書いているとおり

| ファイル                                 | 出自                       |
| ---------------------------------------- | -------------------------- |
| `multi-angle-review.SKILL.md`            | 借りもの（実験的・未安定） |

> おり、**内容は同一**（`diff` で確認済み）。スキルとして有効なのは `.claude/skills/` のほう。
> ここに置いてあるのは borrowed の一式を欠けなく保つため。

## 根ごとのノート

第2巡の作業単位は「指摘」ではなく**根**。1根につき1ファイルを `根A-*.md` の形で置く。

「指摘修正のあり方」の段階に沿って、**段階4まで書き終えてから人間の確認を取り、段階5（修正）へ進む**。

| 段階     | 出力                                                                     |
| -------- | ------------------------------------------------------------------------ |
| 1 理解   | 指摘者の言葉から離して、何の症状かを言い直す                             |
| 2 調査   | 実物で接地する。**欠陥の種類を言葉にして横断で探す。** 修正案を3分類する |
| 3 整合性 | **変更する一文の役割の書き出し**（何を主張／何を運んで／誰が寄りかかる） |
| 4 方針   | 変えるもの・閉じる指摘・影響範囲と変更しない箇所・分類・書かない調査内容 |
| 5 修正   | 方針どおりに当て、書いた内容を検証する                                   |

**段階3を検索で済ませない。** 依存は文字列として一致しない（補遺の実例6）。
